# Architecture (living; update when a batch adds a module, table or route)

## Flow
1. **Intake** (`lib/intake.ts`, `POST /api/intake`): creator paste, DM screenshot, portfolio form, later Postmark email. Public intakes are rate limited and need a one-time email verify.
2. **Extraction** (`lib/ai/extract.ts`, `lib/ai/prompts.ts`): the model lists requested uses, each with an exact quote. It never sets the price.
3. **Checks** (`lib/checks.ts`): quote must exist and support its option; tripwires, negation, unknown sender. Failures route to the creator (`needs_creator`, `clarify`).
4. **Pricing** (`lib/pricing.ts`, `lib/gap.ts`): `gap(requested, current, paidCents, card)` = combined price minus paid, from the frozen rate card. Integer cents.
5. **Versions + policy** (`lib/versions.ts`, `lib/policy.ts`): a pending licence version, then R1 allowed client, R2 per-deal cap, R3 daily + rolling caps, R4 unsellable, R5 ready. All pass = autopilot; any fail = "Ask me" with typed-total approval.
6. **Invoice** (`lib/send.ts`, `lib/paypal/`): PayPal Invoicing v2, Agent Toolkit server-side with REST fallback, both pinned to `credentials().base`. `claim()` under the creator lock writes the `invoices` row (with `recipient_email`) before any PayPal call and re-checks the per-deal cap. The draft is read back (number, USD, amount, no tip, no partial) before `send`. Unknown outcomes are held, not cancelled; Retry reconciles the same invoice number with PayPal first. `markInvoiceCancelled()` is the one cancel transition (batch 6 webhook reuses it).
7. **Payment** (batch 6, `lib/grant.ts`): `grantIfPaid` from webhook, client page re-check, or creator re-check. GETs the invoice by its stored PayPal id (also for a row still `creating`/`created` whose send completion was lost), runs `checkInvoicePaid` (PAID, our number, USD, exact cents, one PAYPAL capture; a missing recipient email or due amount passes only when all of those match), hashes the exact licensed file, then in one transaction under the creator lock and a per-capture lock: current-branch check (parent still active, no other active licence; else `paid_on_stale_version`), payment row (payer email only if PayPal reported it), parent superseded, version `active` with a unique version number, invoice + R3 reservation reconciled, receipt. Term = local midnight of the payment's calendar day in the creator's timezone to the same local day N months later.
   - **Revocation**: a fully REFUNDED/REVERSED capture (re-fetched) revokes that version and every version built on it (parent_id chain), voids their download tokens, issues revocation receipts, and restores the parent if still in term. Pending quotes built on it are marked `withdrawn_at` under the lock first (grant refuses them), then cancelled at PayPal by `withdrawPending()`; unfinished cancellation is retried on every later refund event and creator Re-check. A refund/reversal that arrives before its payment is recorded is read from PayPal under the per-capture lock and kept in `capture_reversals`; a stored REFUNDED/REVERSED is never replaced by a weaker status, and it blocks that grant. A quote PayPal shows paid that grant refused (stale branch, withdrawn, refunded before grant) records `locked_capture_id`; when that capture is fully refunded or reversed (webhook, INVOICE.REFUNDED or creator Re-check) the quote is closed (superseded, invoice refunded, reservation released). Only PAID and PARTIALLY_PAID count as money received; PAYMENT_PENDING is retried and MARKED_AS_PAID is never treated as paid. Partial refunds alert once per refund.
   - **Webhook** (`lib/webhooks.ts`): 400 bad/missing signature (nothing stored), 503 when PayPal could not be asked or work is unfinished (row stays unprocessed for PayPal's retry), 200 processed/duplicate/not ours. Body read with a 256 KB streaming cap and verified byte for byte.
   - **Re-check**: pending -> grant; active or superseded -> GET every recorded capture of the version and the licences it built on. Returns an outcome (granted, already, refused, revoked, partial, unchanged, unavailable) that the deal room shows.
8. **Delivery** (batch 6, `lib/pay.ts`): `/pay/:token` client page (sequence-numbered reads, errors shown with Try again), `/download/:token` (scope-picked file; bytes read first, then the use is taken under the creator lock, so a refund or link replacement committed meanwhile stops it), receipt at `/r/:id` (every body normalized, emails masked). Replacing the client link voids that version's download tokens in the same transaction. Separate hourly per-address budgets: `pay_read` 1200, `pay_check` 240, `pay_preview` 600, `download_issue` 60, `download_serve` 120; PayPal itself is asked at most once per invoice per 10 s.
9. **Renewal + clock** (batch 8, `lib/clock.ts`, `lib/renewal.ts`): `clock.now()` = real time + the `demo_clock` offset in demo mode only. `runTick()` (`POST /api/cron/tick`, `x-cron-secret`; the `/demo` panel) under the creator lock: an active licence within 7 days of its end gets one renewal (`licence_versions.renewal_of`, unique), as a new deal (`briefs.source = 'renewal'`, no AI) with the same scope priced at the current rate card through `gap()`; `evaluate()` at the tick's clock then `sendInvoice()` when the client opted in on the pay page (`renewal_opt_in`) and R1-R5 pass (R5 passes structurally for a same-scope renewal), otherwise the `RENEW` rule holds it in Ask me for the typed total. An active licence past its end expires: status `expired`, download tokens voided, an Expired receipt (`kind: 'expiry'`) and a revocation receipt (both status `expired`), an `expired` event. Renewal grant: parent active or expired, start = later of payment day and parent end day, `paid_cents` = this payment only, parent superseded at payment (one-active index). `GET /healthz` never touches the database.
10. **Later**: Orders rail, v2 receipts (9), AG Studio ledger over `GET /api/ledger`.

## Code map (`app/`)
- `lib/` all logic; `app/api/**/route.ts` thin handlers; `app/(creator)/` dashboard screens (deals, ask, ledger, portfolio, settings); `components/creator`, `components/ui` (shadcn).
- UI (batch 7): tokens in `app/globals.css` (dashboard `:root`/`.dark`, client `.theme-client`, type roles `text-d-page` .. `text-c-id`), fonts via `next/font` in `app/layout.tsx`. Shell `app/(creator)/layout.tsx` + `components/creator/nav.tsx` (side nav, mobile Menu sheet, skip link); shared states in `components/creator/page-bits.tsx`. `GET /api/portfolio` (read-only) lists the creator's photos with their public preview image and `onPublicPage` (`lib/portfolio.ts`, same title join as `/c/[creatorSlug]`). `lib/demo.ts` names the seeded-demo id prefixes; read models project a display-only `demo` flag (deal version invoice, deal row, ledger row, alert) so screens never show demo rows as PayPal evidence. Shared approval field `components/creator/typed-total.tsx` (Ask and deal room). Status words in `lib/format.ts` `STATUS_LABEL`. Client page `/c/[creatorSlug]`: `components/client/*` on `glass.css` (dark cinematic tokens); the hero `globe-hero.tsx` draws DOM photo tiles over a decorative `cobe` 2.0.1 WebGL earth (only third-party runtime dependency added in B7, see `THIRD-PARTY.md`).
- `lib/auth.ts` creator session + same-origin check on every mutation; `lib/server.ts` `guard()` wrapper.
- `lib/reasons.ts` maps every reason code to one plain sentence (deal room, Ask me, ledger).
- `lib/access.ts` `fileAccess(scope, paid)` decides which file a licence may get: print, billboard, out-of-home (OOH) and TV unlock the largest stored rendition (the print file); social and web get the 800px web file.
- `db/migrations/` numbered SQL (001 init, 002 intake, 003 policy, 004 invoice recipient + `autopilot_sends.sent_at`, 005 payments, 006 send attempt, 007 batch-6 review fixes, 008 fix round 2: `locked_capture_id`, `withdraw_state` `refunded`, `rate_hits(at)` index, 009 row seq, 010 batch 8: `licence_versions.renewal_of` + one-renewal index, `demo_clock`); `tests/b6-postgres.test.ts` runs the lock races on real Postgres when `TEST_DATABASE_URL` is set; `db/cli.ts` init / migrate / seed / files; `db/init.ts` `initialize()` = migrate + seed + demo seed + placeholder files. `db/seed.ts` = Imani, card, Northwind v1, 3 named assets + the 24 portfolio photos (`imani/portfolio/NN/*`, public, photos.json order). `db/seed-demo.ts` (batch 7) = 5 more clients and 8 demo deals covering every dashboard state, written through the pure live helpers (`runChecks`, `gap`, `versionHash`, `invoiceNumberFor`, `grantReceiptBody`); ids `INV2-DEMO-`/`SEED-DEMO-`, every event `demo: true`, no `autopilot_sends`.
- `lib/tokens.ts` 32-byte bearer tokens, sha256 at rest, AES-GCM for the stored pay link with a key from `APP_SECRET` only (no fallback). `publicBase()` = `PUBLIC_BASE_URL` origin for every absolute client link.
- `lib/access.ts` also has `licensedFile()` / `licensedKey()`, shared by grant (fingerprint), receipts and downloads. `lib/receipts.ts` `grantReceiptBody()` is the one receipt producer (seed uses it too); `normalizeReceiptBody()` reads any stored body.
- `lib/rate-limit.ts` prunes rate-hit rows older than the one-hour window on each hit. Tests in `tests/` (PGlite; `LIVE_PAYPAL=1` for sandbox, refuses any non-sandbox host).
- `lib/server.ts` `setRouteDepsForTests()` lets route tests run the real handlers on PGlite with mocked PayPal (refused in production).
- `lib/server.ts` keeps the database promise on `globalThis`, because Next bundles pages and route handlers apart with a module copy each. One database per process, on PGlite and Postgres.
- `lib/reply-draft.ts` `replyDraft(view)`: the client reply shown in the deal room, built from the BriefView only (kept sentences, `gapPreview` lines, `invoice.payUrl`). No model call; the app sends nothing. A paid-use stop gets an offer with no figure; renewals get none.
- `lib/proof.ts` `paymentProof(q, versionId)` (B12 D1): PayPal invoice id and number, the newest `grant` event (each PayPal re-fetch by grantIfPaid) and the newest `webhook_events` row for the invoice or its capture (only signature-verified events are stored). On `BriefView.proof` and `ReceiptView.proof`; null for seeded invoices. Display only.
- `lib/agent-door.ts` (B12 D2): `agentQuote` and `verifyReceipt` behind `GET /api/agent/quote` and `GET /api/agent/receipt`. Read-only apart from a per-IP `rateLimit('agent')` hit (120 an hour); a paid-promotion use gets 422 with no figure; requests go through the existing `POST /api/intake`.
- R3 daily count starts at the creator's local midnight (`startOfDayIn`, correct on clock-change days) and counts sent rows by `sent_at` plus live reservations.

## Tables (spec §7)
clients, creator_settings, assets (+ is_public), rate_card_options, briefs, transcripts, extractions, licence_versions (frozen card, content hash; `withdrawn_at`/`withdraw_state` for quotes withdrawn after a parent refund; unique index: one `active` per client + asset), invoices (+ pay token hash/ciphertext, `last_checked_at`), orders, payments (unique PayPal txn id, `paid_at`, `payer_email` from PayPal only), approvals, autopilot_sends (cap reservations), scheduled_actions, receipts (32-byte public id), events (ledger; alerts carry `evidenceKey` for de-duplication), webhook_events (unique event id, `processed_at`, `error`), download_tokens, rate_hits, capture_reversals (refund/reversal seen before its payment), email_verifications.

## External
PayPal sandbox (Invoicing v2, Orders v2, webhooks, Agent Toolkit), Supabase (Postgres + private Storage), Render (host + daily tick), LLM via one adapter. Postmark is deferred until after Nov 9, and AG Studio is decided Nov 7 (`docs/batch-9-win.md`).

## B10 and B11 additions (2026-11-05)
- **File store** (`lib/storage.ts`): `readAsset`/`putAsset` use a local directory by default and a private Supabase Storage bucket when `SUPABASE_URL` is set, over plain `fetch`. `ensureStore` (called from `ensureAssetFiles`, so from `db:init`) creates the bucket and refuses a public one, and the first file operation of each server process runs the same check. Either half of the Supabase pair refuses, and so does Render (the `RENDER` variable it sets) with neither; a local production run with neither keeps the disk. `saveUpload`/`readUpload` do the same for DM screenshots; `briefs.upload_path` holds a local path or `bucket:<key>`. No URL to a file ever leaves the server.
- **Deploy:** `render.yaml` (web service from `app/`), `.github/workflows/daily-tick.yml` (daily `POST /api/cron/tick` through Dec 15), both from the public repo's default branch, the only branch GitHub schedules from. Order and names: `README.md`.
- **Paid use** (`lib/reasons.ts` `PAID_PROMO_TRIPWIRES`, the one source; `hasPaidUse`): these tripwires are not reviewable in `lib/checks.ts`. `saleRefusal` (`lib/versions.ts`) returns `paid_use_unpriced`. `pendingVersionFor` uses it so no new version is made, and `claim()` in `lib/send.ts` uses it at the first-send boundary, so a quote made earlier cannot reach PayPal by Approve, Ask, Retry or autopilot. It reads the quote's own extraction, including notes from an edit made before B11. A sent invoice is not re-checked. Reconcile deletes an unsent draft only on an exact PayPal `DRAFT` status, and cancels the row only after that delete succeeds and only if the row is still `creating` or `created`; otherwise the row and reservation stay for a later attempt. `getBriefView` and `listDeals` return no price on this stop, so every screen shows none; other tripwires are unchanged.
- **Not for sale:** `saleRefusal` refuses the seeded placeholder (`PLACEHOLDER_ASSET_KEY`) with `asset_not_for_sale`, at the same two places. A private real photo still sells. The pickers already hide private photos.
- **Read model:** `BriefView.sentBy` ('agent' when a real invoice went out with no approval row, 'you' with one, null otherwise) and `BriefView.renewalParent` (the licence a renewal renews; display only, the price path is unchanged).
- **Pay page:** a throttled manual check re-checks itself once after 11 s (`components/client/pay-client.tsx`).
